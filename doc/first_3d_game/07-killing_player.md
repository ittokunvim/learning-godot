# プレイヤーに死亡判定を設定する

> 参考：https://docs.godotengine.org/ja/4.x/getting_started/first_3d_game/07.killing_player.html

敵を踏み潰せるようになりましたが、まだゲームオーバーになりません。

敵に殴られた場合と押し潰された場合で、当たり判定を変えたいです。
プレイヤーが床を動いている時はやられて、空中にいる時はやられないようにします。
2種類の衝突を区別するためにベクトル演算ノードを使うことも可能です。
しかしここでは代わりにArea3Dノードを使います。
こちらの方がHitboxに適しています。

## Areaノードによるヒットボックス

プレイヤーにMobDetectorという名前のArea3Dノードを追加します。
そしてMobDetectorノードにCollisionShape3Dノードを追加します。

追加したらインスペクタでShapeプロパティにCylinderShape3Dを割り当てます。

ここではプレイヤーが地面やそれに近いところにいるときだけ衝突が起きるようにします。
シリンダーの高さを小さくしてキャラクターの上部に移動させます。
こうすることでプレイヤーがジャンプした時に形状が高すぎて敵が衝突しにくくなります。

またシリンダーの幅は球より広くします。
こうすると衝突してモンスターのコリジョンボックスの上に押し出される前に、プレイヤーに当たることになります。

シリンダーの幅が広いほどプレイヤーはやられやすくなります。

次にMobDetectorノードのMonitorableプロパティをオフにします。
これにより他の物理ノードがその領域を検出できないようにします。
補完的なMonitoringプロパティにより衝突を検出することができます。
次にコリジョン、レイヤーの値を削除し、マスクを敵に設定します。

エリアが衝突を検知するとシグナルを発信します。
そのうちの1つをプレイヤーノードに接続しましょう。
MobDetectorのSignalsドックに移動し、`body_entered`シグナルをPlayerに接続します。

`CharacterBody3D, RigidBody3D`ノードが入った時に、MobDetectorは`body_entered`を発信します。
敵の物理レイヤーをマスクするだけなので`Mob`ノードのみが検出されます。

コードでは、ゲームを終了するために後で使用するシグナルを発信してプレイヤーを削除します。
これらの操作を`die()`関数でラップすることにより、コードに説明的なラベルをつけることができます。

```godotengine
# Emitted when the player was hit by a mob.
# Put this at the top of the script.
signal hit


# And this function at the bottom.
func die():
	hit.emit()
	queue_free()


func _on_mob_detector_body_entered(body):
	die()
```

## ゲームオーバーを設定する

ゲームオーバーはプレイヤーの`hit`シグナルを使用して実装することができます。
メインノードに接続して、`MobTimer`を止めます。

メインシーンを開いてプレイヤーノードを選択し、シグナルドックを開き、`hit`シグナルをMainノードに接続します。

これで`_on_player_hit()`関数の中でTimerを取得し、停止することができます。

```godotengine
func _on_player_hit():
	$MobTimer.stop()
```

ゲームをテストしてみると、プレイヤーがやられるとモンスターの出現が止まり、残ったモンスターもスクリーンから去っていきます。

またプレイヤーがやられた際にゲームがクラッシュしなくなります。
これはMobTimerを停止したことで`_on_mob_timer_timeout()`関数が実行されなくなったためです。

また敵がプレイヤーに衝突してやられたかはプレイヤーとモブの衝突判定のサイズと位置によって決まります。
プレイヤーの感覚に合ったゲーム体験を実現するためには、衝突判定を動かしたり、サイズを変更したりして調整する必要があるかもしれません。

ここで3Dゲームの試作が完成しました！

ここからスコア表示やリトライの仕組みなどを追加し、最小限のアニメーションでゲームをより良いものにしていきます。
