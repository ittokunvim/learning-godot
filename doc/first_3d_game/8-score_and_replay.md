# スコアとリプレイ

> 参考：https://docs.godotengine.org/ja/4.x/getting_started/first_3d_game/08.score_and_replay.html

このパートでは、スコア表示、音楽再生、リプレイ機能を追加します。

現在のスコアを変数に記録し、最小限のインターフェイスで画面に表示する必要があります。
そのためにテキストラベルを使用します。

メインシーンでUserInterfaceという名前のControlをMainに追加します。
そしてScoreLabelという名前のLabelノードをUserInterfaceに追加します。

インスペクタでLabelのTextに`Score: 0`という文字列を設定します。

またテキストはデフォルトで白色なので、色を変更する必要があります。

Colorセクションを開き、Font Colorチェックボックスをオンにし、テキストを黒に設定します。

最後にテキストの位置を左上隅に移動します。

UserInterfaceノードを使うと、UIをシーンの中で1つのツリー状にまとめることができ、テーマリソースを使うことができます。
このUserInterfaceノードを使用して、ゲームのフォントを設定します。

## UIテーマの作成

UserInterfaceノードを選択し、インスペクタでThemeセクションを開き、Themeに新しいテーマリソースを作成します。

ThemeをクリックするとGodotの下のパネルにあるテームというエディタが開きます。
デフォルトのプレビュー内では、すでに用意されているすべてのUIウィジェットがテーマリソースがあり、プレビューで確認できます。

デフォルトではテーマにはプロパティが少ないです。

デフォルトフォントは、一般的なコンピュータの規定フォントファイルを想定しています。
形式は`True Type(TTF), OpenType(OTF)`の2種類です。

ではフォントを設定します。
ファイルシステムドックで`Montserrat-Medium.ttf`ファイルをThemeのDefault Fontにドラッグします。
そして文字が小さいのでフォントサイズを`22`ピクセルに設定します。

## スコアの記録

次にスコア表示に取り掛かりましょう。
ScoreLabelにスクリプトをアタッチし、以下のコードを記述します。

```godotengine
extends Label

var score = 0
```

敵モンスターを踏みつけるたびにスコアが1ずつ増えるようにします。
倒したイベントは`squashed`シグナルを使って検知可能です。
しかしプログラムコードからモンスターをインスタンス化しているので、エディタを使ってシグナルを`ScoreLabel`に接続することはできません。

その代わりにモンスターを出現させるたびにコードから接続する必要があります。

`main.gd`の`_on_mob_timer_timeout()`関数の末尾に以下のコードを記述します。

```godotengine
mob.squashed.connect($UserInterface/ScoreLabel._on_mob_squashed.bind())
```

この処理は`squashed`シグナルを発信すると、ScoreLabelノードがそれを受け取り、`_on_mob_squashed()`関数を呼び出すという処理です。

`score_label.gd`で`_on_mob_squashed()`関数を定義します。

```godotengine
func _on_mob_squashed():
	score += 1
	text = "Score: %s" % score
```

これで敵を踏みつけるたびにスコアが増えていきます。

> 複雑なゲームでは、UIをゲームの世界から切り離したい場合があります。
> その場合、ラベルにスコアを表示させることもなくなるかもしれません。
> その代わり、スコアを別の専用オブジェクトに格納することもできます。
> しかしここで作成しているゲームの規模は大きくないのでシンプルな方法をとっています。
> プログラミングは、常にバランスを取って進めることが大切です。

## ゲームをリトライする

ゲームオーバーになった後にリトライできる機能を追加します。
プレイヤーがゲームオーバーになった場合、画面にメッセージを表示して入力を待つ機能を作ります。

Retryという名前のColorRectノードをUserInterfaceノードに追加します。
このノードは長方形を単色で塗りつぶし、画面を暗くするオーバーレイとして機能します。

ビューポート全体を覆うようにするには、ツールバーのアンカープリセットメニューを使用します。

メニューでRect全面を適用します。
UserInterfaceを選択し、インスペクタでレイアウト、アンカー、Rect全面を適用します。
Retryを選択し、インスペクタでColorを暗くて透明なものに設定します。

次にLabelをRetryの子ノードに追加し、Textに`Press Enter to retry.`と入力します。
このLabelを動かして画面の中央に固定するには、アンカーで中央に設定します。

### リトライ機能をコーディング

プレイヤーがゲームオーバーになってリトライする時に`Retry`ノードを表示したり隠したりするコードに取り掛かります。

`main.gd`でまず、ゲーム開始時点でリトライするオーバーレイを隠しておく必要があります。

```godotengine
func _ready():
	$UserInterface/Retry.hide()
```

そしてプレイヤーが敵から攻撃を受けた時にオーバーレイを表示します。

```godotengine
func _on_player_hit():
	#...
	$UserInterface/Retry.show()
```

最後にRetryノードが表示されたら、プレイヤーの入力待ち状態にして、プレイヤーがエンターキーを押したらゲームをリスタートする必要があります。
これにはGodotですでに用意されている`_unhandled_input()`コールバック関数を使用します。
この関数はプレイヤーがどんなキーを押しても動作する関数です。

プレイヤーが`ui_accept`としてあらかじめ設定しておいた入力を行います。
その時に`Retry`オーバーレイが表示されている場合、現在のシーンをリロードします。

```godotengine
func _unhandled_input(event):
	if event.is_action_pressed("ui_accept") and $UserInterface/Retry.visible:
		# This restarts the current scene.
		get_tree().reload_current_scene()
```

`get_tree()`はグローバルなSceneTreeオブジェクトにアクセスできる関数です。
そのためこの関数は現在のシーンをリロード、リスタートさせることができます。

## 音楽を追加する

バックグラウンドで音楽を追加するには、Godotの別の機能である`autoloads`を使用します。

オーディオを再生するにはAudioStreamPlayerノードを追加し、オーディオファイルを添付するだけで再生できるようになります。
シーンを開始すると自動的にオーディオが再生されます。
しかしシーンをリロードすると、オーディオノードもリセットされ、音楽が最初から始まってしまいます。

オートロード機能を使えば、ゲーム開始時に現在のシーン以外のノードやシーンをGodotに自動的にロードさせることができます。
またグローバルにアクセス可能なオブジェクトを作成する場合にも使用できます。

新規シーンを作成します。
その他ノードでAudioStreamPlayerを作成し、名前をMusicPlayerとします。

`House In a Forest Loop.ogg`というサウンドトラックを、インスペクターのStreamプロパティにドラッグします。
またAutoplayのチェックボックスをオンにして、ゲーム開始時に自動的に音楽が再生されるようにします。

シーンは`music_player.tscn`で保存します。

シーンを自動ロードとして登録する必要があります。
プロジェクト設定、グローバル、自動読み込みタブに移動し、パスフィールドにシーンへのパスを入力します。
フォルダアイコンをクリックし、`music_player.tscn`を選択し、追加ボタンでノードを登録します。

これで`music_player.tscn`がどのシーンでもロードされるようになりました。
テストを実行すると、シーンドックが、リモートとローカルの2つのタブに変わります。

リモートタブでは実行中のゲームのノードツリーを視覚化することができます。
そこではメインノードとシーンに含まれるすべてのもの、そしてインスタンス化されたモブキャラクターのノードが一番下に表示されます。

一番上にはオートロードされたMusicPlayerと、その上に`root`ノードがあります。
`root`ノードはゲームのビューポートになります。
