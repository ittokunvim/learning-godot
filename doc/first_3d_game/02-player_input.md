# プレイヤーシーンと入力アクション

> 参考：https://docs.godotengine.org/ja/4.x/getting_started/first_3d_game/02.player_input.html

ここではプレイヤーシーンをデザインし、入力アクションの登録、動きをコーディングします。
最後には八方向に動くプレイ可能なキャラクターが完成します。

ではシーンを新規作成して、Playerという名前のCharacterBody3Dノードを作成します。
このノードは2Dゲームチュートリアルで使用されるエリアやリジッドボディを補完するものです。
リジッドボディ同様に、キャラクターボディも移動したり環境と衝突したりできます。
しかし物理エンジンによって制御されるのではなく、その動きを直接指定します。
ジャンプやスクイズの仕組みをコーディングする際に、このノードの独自の機能をどのように活用するかみていきます。

とりあえず、キャラクターの3Dモデルに対して基本的なリグを作成します。
のちにアニメーションを再生しながら、コードを使用してモデルを回転させることができます。

ではPlayerノードにPivotというNode3Dノードを追加します。
次に`art`フォルダ内から`player.glb`をPivotノードにドロップします。
これでPivotの子としてモデルがインスタンス化されるはずです。
このノードの名前をCharacterとします。

> `glb`ファイルは、オープンソースのglTF2.0仕様に基づく3Dシーンデータを含んでいます。
> これはFBXのような独自のフォーマットに代わる、現代的で強力なフォーマットです。
> これらのファイルを作成するには、Blenderでモデルを設計し、それをglTFにエクスポートします。

あらゆる物理ノードと同様に、キャラクターが環境と衝突するためには衝突形状が必要です。
Playerノードを選択し、CollisionShape3Dを子ノードに追加します。
インスペクタのShapeプロパティにSphereShape3Dを指定します。

表示されるワイヤーフレームは物理エンジンが衝突判定する際に使用する型になります。
これをフィットさせたいので、キャラクターのサイズに合わせて少し縮小します。
大体球体の半径は`0.8`です。

次に衝突のための型を上に移動して、型のそこがグリッドの平面と同じにします。

形状の移動を簡単にするために、Character, Pivotノードの横にある目のアイコンをクリックすることで表示を切り替えられます。

ノードの準備ができたので、ほとんどコーディングできるようになりました。
しかしその前に、いくつかの入力アクションを定義する必要があります。

## 入力アクションの作成

キャラクタを動かすために矢印キーでプレイヤーの入力操作を認識する必要があります。
Godotではキーバインドをコードで記述できますが、キーやボタンのセットに操作のラベルを割り当てる機能があります。
この機能により、スクリプトをシンプルで読みやすくすることができます。

ではプロジェクト設定、インプットマップを開きます。
これから定義するアクションは、`move_left, move_right, move_forward, move_back, jump`とします。

5つのアクションを定義できたら、`move_`のアクションにそれぞれ`WASD`キーと矢印キーを割り当てます。
あとはゲームパッドのジョイスティックの対応も追加します。
＋ボタンをクリックし、`Joypad Axes`でそれぞれの方向の値を選択します。

最後に`jump`の値を`Joypad Buttons 0`と`Space`を割り当てます。

これでゲームに必要なアクションが用意できました！
このメニューを使ってプロジェクト内のキーやボタンのグループにラベルをつけることができます。
